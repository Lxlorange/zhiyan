# 需求-模块10-前端信息架构与交互体验

## 1. 模块定位

本文档定义重构后的前端产品结构。目标是让平台从“功能堆叠页面”变成围绕科研方向学习的现代 AI 学习产品。

## 2. 总体导航

登录后主导航建议为：

- 探索方向。
- 学习项目。
- AI 课堂。
- 每日计划。
- 科研工具。
- 文献知识库。
- 画像设置。
- 教师驾驶舱。

## 3. 首页

首页不展示画像，不展示大段资源，而是展示：

- 当前学习项目。
- 今日任务。
- 继续学习按钮。
- 最近课堂。
- 当前薄弱点简要提示。
- 推荐新方向。
- 科研工具快捷入口。

## 4. 探索方向页

页面目标：

- 帮助用户输入科研方向。
- 展示方向理解结果。
- 创建学习项目。

页面组件：

- 大输入框。
- 方向模板卡片。
- 澄清问题区。
- 方向理解结果卡。
- 创建项目按钮。

## 5. 学习项目页

页面目标：

- 管理用户所有学习项目。

页面组件：

- 项目列表。
- 项目进度。
- 当前阶段。
- 最近学习时间。
- 进入项目按钮。
- 归档按钮。

## 6. 学习清单页

页面目标：

- 展示和编辑学习清单。

页面组件：

- 阶段分组。
- 学习项卡片。
- 拖拽排序。
- 类型标签。
- 难度标签。
- 预计时长。
- 推荐理由。
- 编辑弹窗。
- 保存版本按钮。
- 生成每日计划按钮。

## 7. AI 课堂页

页面目标：

- 提供持续对话式课堂。

页面布局：

- 左侧：课堂目录和学习目标。
- 中间：对话与内容卡片。
- 右侧：知识点、来源、进度、快捷操作。
- 底部：输入框。

快捷操作：

- 讲简单点。
- 举例。
- 画图。
- 出题。
- 生成 demo。
- 总结。
- 下一步。

## 8. 每日计划页

页面目标：

- 让用户每天继续学习。

页面组件：

- 今日计划。
- 任务列表。
- 总预计时长。
- 完成按钮。
- 延后按钮。
- 跳过按钮。
- 进入课堂按钮。
- 明日预告。
- 周复盘入口。

## 9. 科研工具页

页面目标：

- 提供论文和科研写作工具。

工具卡片：

- 论文精读。
- 论文润色。
- 综述大纲。
- 引用格式。
- 报告检查。
- 文献管理。

每个工具应进入独立工作流页面，不要都堆在一个表单里。

## 10. 文献知识库页

页面目标：

- 管理用户文献和个人知识。

页面组件：

- 文献列表。
- 标签筛选。
- 阅读状态筛选。
- 上传入口。
- 精读笔记。
- 知识库检索。
- 关联学习项目。

## 11. 画像设置页

页面目标：

- 后台化展示画像条目。

页面组件：

- 维度分组。
- 条目卡片。
- 置信度。
- 来源。
- 启用开关。
- 编辑按钮。
- 删除按钮。
- 版本历史。

## 12. 教师驾驶舱

页面目标：

- 展示班级方向、短板、资源和计划情况。

页面组件：

- 班级方向分布。
- 高频知识短板。
- 学习计划完成率。
- 高风险学生。
- 资源使用统计。
- Agent 任务统计。

## 13. 全局交互要求

- 任意 API 错误必须弹窗显示。
- 长任务必须展示 Agent 执行进度。
- 生成内容应分卡片展示。
- 大段文本应折叠。
- 所有 AI 结果应能重新生成。
- 用户编辑优先于 AI 推荐。
- 页面应避免把所有功能堆在一起。

## 14. 视觉要求

- 应像现代 AI 学习产品，而不是后台管理系统。
- 卡片用于具体内容，不用于嵌套整页。
- 学习任务应清晰、可操作。
- 课堂内容应适合阅读和互动。
- 错误、加载、空状态必须完整。

## 15. 验收标准

- 用户能从首页进入当前学习项目。
- 用户能创建方向、保存清单、进入课堂、完成每日计划。
- 科研工具和画像设置是独立模块。
- 所有 API 错误都有弹窗。
- 页面结构不再是一页堆满所有内容。
