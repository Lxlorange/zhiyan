# 智研星链 A3 项目介绍（功能模块版）

## 1. 项目定位

智研星链 A3 是面向“基于大模型的个性化资源生成与学习多智能体系统开发”赛题的一体化 AI 学习平台。系统围绕高校学生的课程学习、科研入门、实验复现、论文写作和答辩训练等场景，提供从“自然语言提出学习/科研目标”到“生成项目、学习清单、每日计划、AI 课堂、多模态资源、练习评估和画像更新”的完整闭环。

平台的核心思想不是让学生先填写复杂表单，而是让学生以对话方式表达目标、上传参考资料、持续微调计划。系统在后台维护学生画像、知识库、学习状态、错题记录、课堂产物和 Agent 任务记录，并基于这些数据生成更个性化的学习路径与学习资源。

## 2. 总体架构

### 2.1 技术栈

- 前端：Vue 3、Vite、TypeScript、Element Plus、Vue Router、Vue Flow。
- 后端：FastAPI、SQLAlchemy、Pydantic、PostgreSQL、pgvector。
- AI 调用：OpenAI 兼容接口形式接入千问/Qwen，统一封装在后端 LLM client 与各业务 service 中。
- 文档解析与知识库：支持 PDF、PPTX、PPT、DOCX、Markdown、文本、图片、ZIP 包解析，结合 OCR、LibreOffice、Tesseract、pgvector 检索增强。
- 课件与课堂资源：python-pptx 生成 PPTX，HTML/SVG/Three.js 生成互动演示，浏览器 SpeechSynthesis 与预留科大讯飞 TTS 入口支持语音讲解扩展。
- 部署：Docker Compose，PostgreSQL + Backend + Frontend + Caddy；支持生产环境 `.env.production` 配置。

### 2.2 前后端分层

前端采用路由化页面结构，不再是单页静态堆叠：

- `/directions`：探索方向与项目计划生成。
- `/projects`、`/projects/:projectId`：项目主页。
- `/projects/:projectId/syllabus`：项目学习清单。
- `/projects/:projectId/syllabus/items/:itemId/classroom`：集成 AI 课堂。
- `/daily-plan`、`/projects/:projectId/daily-plan`：每日计划。
- `/profile`、`/resources`、`/tutor`、`/assessment`、`/literature`、`/writing`、`/methods`：学习工作台与科研工具。
- `/agents`：多智能体运行与教师视角面板。
- `/settings`：账号与基本信息设置。
- `/signin`：独立登录/注册页。

后端按领域拆分 API：

- `routes_auth.py`：认证与用户信息。
- `routes_directions.py`：方向探索、项目计划、项目管理。
- `routes_syllabus.py`：学习清单、每日计划。
- `routes_classroom.py`：课堂、课件、演示、答题、实操、复盘。
- `routes_course.py`：课程知识库、资料导入、检索增强。
- `routes_profile.py`：对话式画像。
- `routes_workspace.py`：画像中心、文献、科研工具、工作台概览。
- `routes_teacher.py`：教师/管理视角。
- `routes_workflow.py`：早期完整链路演示与健康检查。

## 4. 探索方向与项目计划模块

探索方向页面是系统入口，目标是把用户的一句话学习/科研想法转化为可执行项目。

### 4.1 AI Agent 聊天式输入

用户可输入学习目标，例如：

- “我想用 WiFi 信号做跌倒检测。”
- “请从 U-Net 入手，全面介绍语义分割。”
- “我想系统学习 Python。”
- “我需要完成一篇课程论文并准备答辩。”

输入区支持：

- 学习类型选择：课程项目、科研项目、课程知识等。
- 学习目标。
- 补充要求。
- 参考资料上传。
- 流式生成项目计划。
- 持续对话调整计划。
- 确认后构建项目。

### 4.2 附件解析

项目计划支持上传参考资料，后端会真实解析附件正文后送入 AI 链路，而不是只把文件名作为提示。当前支持：

- PDF。
- Markdown。
- 文本资料。
- 后续知识库导入模块支持更多文件类型。

解析失败时系统按 fail-closed 原则返回明确错误，不使用文件名猜测内容，不生成备用计划。

### 4.3 项目构建

用户对项目计划满意后点击构建项目，系统会创建：

- 研究方向记录。
- 学习项目。
- 项目事件。
- 后续学习清单与资源生成入口。

核心接口：

- `POST /api/project-plans/attachments/parse`
- `POST /api/project-plans/stream`
- `POST /api/project-plans/{plan_id}/messages`
- `POST /api/project-plans/{plan_id}/messages/stream`
- `POST /api/project-plans/{plan_id}/build`
- `GET /api/learning-projects`
- `GET /api/learning-projects/{project_id}`
- `GET /api/learning-projects/{project_id}/home`

## 5. 学习项目主页模块

项目主页是用户所有课程项目、科研项目和学习项目的集合入口。

主要能力：

- 查看所有学习项目。
- 查看项目进度、当前阶段、下一步建议。
- 查看今日推荐、最近课堂、当前薄弱点、输出清单。
- 进入项目学习清单。
- 进入项目每日计划。
- 暂停、恢复、归档、复制项目。
- 请求重新生成学习清单。

项目数据持久化在 `learning_projects` 表中，记录学习目标、研究方向、相关课程、知识点、资源数量、完成数量、风险提示和个性化策略。

## 6. 学习清单模块

学习清单是项目的“目录总览”，每个项目都有独立的清单，而不是全局固定清单。

### 6.1 清单生成

系统基于项目目标、学生画像、知识库检索结果和课程结构生成清单。清单包含多个学习项，每个学习项包括：

- 标题。
- 类型。
- 阶段。
- 难度。
- 预计学习时间。
- 推荐理由。
- 学习目标。
- 前置知识。
- 知识点。
- 关联资料。
- 推荐资源类型。
- 课堂类型。
- 完成标准。
- 评估方式。
- 学习状态。

### 6.2 清单编辑

用户可对清单进行调整：

- 新增学习项。
- 修改学习项。
- 删除学习项。
- 拆分学习项。
- 合并学习项。
- 重排学习项。
- 重新生成某一阶段。
- 适配项目变化。
- 激活不同版本。
- 对比不同版本。

### 6.3 版本管理

学习清单使用版本机制：

- `learning_syllabus_versions` 保存清单版本。
- `learning_syllabus_items` 保存学习项。
- `learning_syllabus_operations` 保存用户调整操作。

这样可以保留 AI 生成、用户微调、再次生成之间的演化历史。

核心接口：

- `POST /api/learning-projects/{project_id}/syllabus/generate`
- `POST /api/learning-projects/{project_id}/syllabus/ensure`
- `GET /api/learning-projects/{project_id}/syllabus`
- `GET /api/learning-projects/{project_id}/syllabus/versions`
- `POST /api/syllabus-versions/{version_id}/items`
- `PATCH /api/syllabus-items/{item_id}`
- `DELETE /api/syllabus-items/{item_id}`
- `POST /api/syllabus-versions/{version_id}/reorder`
- `POST /api/syllabus-items/{item_id}/split`
- `POST /api/syllabus-items/merge`

## 7. 每日计划模块

每日计划模块把学习清单转换为类似 Todo 的日程安排。

### 7.1 自动排期

用户生成项目后，系统可根据：

- 当前日期。
- 每日学习时长。
- 是否周末学习。
- 可学习星期。
- 学习项顺序。
- 每个学习项预计分钟数。

自动把清单学习项排入未来日期。如果某一天剩余时间不足，则顺延到下一个可学习日期，直到所有学习项排完。

### 7.2 用户调整

用户可以：

- 查看今日任务。
- 查看逾期任务。
- 查看未来任务。
- 将计划移动到指定日期。
- 将任务向前或向后顺延。
- 点击任务进入对应课堂。
- 与每日计划 Coach 对话，获得学习建议。

设计原则：

- 每日计划不直接删除课程。
- 删除课程应在学习清单中完成。
- 每日计划只负责安排、提前、推迟和继续学习。

核心接口：

- `POST /api/learning-projects/{project_id}/daily-plan/generate`
- `GET /api/learning-projects/{project_id}/daily-plans`
- `GET /api/daily-plans/{plan_id}`
- `PATCH /api/daily-plan-items/{item_id}/schedule`
- `PATCH /api/daily-plan-items/{item_id}/shift`
- `POST /api/daily-plans/{plan_id}/coach`

## 8. 集成 AI 课堂模块

课堂模块是当前平台最核心的学习体验。用户从学习清单点击“开启学习”进入课堂，课堂不是简单浏览页面，而是按步骤完成学习。

### 8.1 课堂生成

课堂基于学习项和知识库生成完整课堂包，包含：

- 课堂标题。
- 学习摘要。
- 动态 PPT 页面。
- 概念卡片。
- Mermaid/图解结构。
- 引导问题。
- 语音讲解脚本。
- 复现实操 Demo。
- 推荐阅读。
- 选择题例题。
- 实操任务。
- 复盘问题。
- 安全与边界提示。

课堂包由多类 Agent 协同生成：

- PlannerAgent。
- SlideWriterAgent。
- VisualDesignerAgent。
- TutorAgent。
- ExerciseAgent。
- DemoAgent。
- SafetyAgent。

### 8.2 PPT 与动态课件

课堂会生成 PPTX 文件，同时在页面中以动态课件形式展示。每页包含：

- 标题。
- 课堂要点。
- 视觉块。
- 侧边信息。
- 示例。
- 易错点。
- 引导问题。
- 来源引用。
- 教师讲解稿。

系统已对生成内容做结构校验和文本清洗，减少纯文字堆叠、字段错位和乱码控制字符对展示的影响。

### 8.3 讲解、笔记与思维导图

课堂提供工具面板：

- 讲解：围绕当前页生成讲解字幕，并可结合浏览器语音播放。
- 互动：针对当前页生成合适的互动演示。
- 产物：记录 Markdown 笔记，引用当前页；生成可编辑思维导图。

笔记保存后作为课堂提交记录持久化，可用于后续知识库与学习画像整合。

### 8.4 互动演示

互动演示参考 OpenMAIC 的 scene/widget 思路，不再强行把所有内容生成 3D。

系统会按内容选择：

- 图解：适合概念关系、系统结构、论文脉络。
- 模拟：适合算法迭代、状态变化、数据流和协议交互。
- 代码：适合 Python、工程复现、实验脚本。
- 时间线：适合科研计划、论文写作、答辩准备。
- 3D：只用于确实需要空间、物理、几何、机械、传感器布置理解的内容。

前端允许用户选择演示形态，默认自动。后端对模型输出做严格结构校验，缺少节点、边、帧或 3D 场景字段时直接返回错误，不生成默认替代内容。

### 8.5 例题与错题

课堂例题已从填空式改为选择题：

- 单选题。
- 多选题。
- 选项结构。
- 正确答案。
- 答错提示。
- 解析。
- 知识点。
- 难度。

学生提交后，系统本地判分：

- 展示答对数量和分数。
- 每题展示正确/需复习。
- 答错时显示提示和解析。
- 未通过时可继续修改并再次提交。
- 错题会写入 `submission_type="mistake"`，为后续错题本和画像更新提供数据。

### 8.6 实操与复盘

课堂完成不是只翻完 PPT：

1. 学生需要浏览完所有课件页。
2. 完成选择题并达到通过标准。
3. 提交实操产物、关键结果和报告。
4. 提交复盘、未解决问题和下一步行动。
5. 系统根据答题、实操和复盘状态自动更新学习项完成度。

核心接口：

- `POST /api/syllabus-items/{item_id}/classroom`
- `POST /api/classroom-sessions/{session_id}/ppt`
- `GET /api/classroom-sessions/{session_id}`
- `POST /api/classroom-sessions/{session_id}/visualization`
- `POST /api/classroom-sessions/{session_id}/voice`
- `POST /api/classroom-sessions/{session_id}/notes`
- `POST /api/classroom-sessions/{session_id}/dialogue`
- `POST /api/classroom-sessions/{session_id}/slides/complete`
- `POST /api/classroom-sessions/{session_id}/quiz`
- `POST /api/classroom-sessions/{session_id}/practice`
- `POST /api/classroom-sessions/{session_id}/reflection`
- `GET /api/classroom-resources/{resource_id}/download`
- `GET /api/classroom-resources/{resource_id}/view`

## 9. 对话式学习画像模块

画像模块用于满足赛题中“通过自然语言对话构建动态学生画像”的要求。

当前画像包含并持久化：

- 学生专业或方向。
- 知识基础。
- 学习目标。
- 学习历史。
- 认知风格。
- 易错点。

- `PATCH /api/workspace/profile/entries`

## 10. 课程知识库与 RAG 模块

知识库模块用于把本地课程资料、课件、习题解析和参考材料变成系统可检索输入。

### 10.1 初始知识结构

系统支持课程、章节、知识点、文档和文档块：

- `courses`
- `course_chapters`
- `knowledge_points`
- `knowledge_documents`
- `document_chunks`

知识点记录前置知识、标签和难度；文档块记录页码、幻灯片编号、章节标题、关键词、embedding 和检索权重。

### 10.2 文件导入

知识库导入支持：

- ZIP 包。
- PDF。
- PPTX。
- PPT。
- DOCX。
- Markdown。
- TXT。
- 图片。

解析能力包括：

- PPTX 幻灯片文本抽取。
- DOCX 段落抽取。
- PDF 文本抽取。
- 图片/PDF OCR。
- 旧版 Office 文档通过 LibreOffice 转换。
- 文档切块。
- 关键词抽取。
- embedding 生成和重建。
- pgvector 检索。

### 10.3 检索增强

后续的项目计划、学习清单、课堂、辅导和资源生成会调用知识库检索上下文，减少模型凭空生成。

核心接口：

- `GET /api/course/map`
- `GET /api/course/knowledge-points`
- `POST /api/course/knowledge/search`
- `POST /api/course/knowledge/search/enhanced`
- `POST /api/course/knowledge/import`
- `GET /api/course/knowledge/import-jobs`
- `GET /api/course/knowledge/import-jobs/{job_id}`
- `POST /api/course/knowledge/embeddings/rebuild`

## 12. 多智能体协同模块

系统以多 Agent 链路组织不同任务，而不是让一个模型一次性生成全部内容。

已在页面和任务记录中体现的 Agent 包括：

- DirectionAgent：识别科研方向、目标类型和澄清问题。
- ProfileAgent：抽取画像条目、证据和置信度。
- SyllabusAgent：生成个性化学习清单并绑定知识库来源。
- KnowledgeBaseAgent：检索课程资料和知识点。
- PlannerAgent：计算每日计划和学习顺序。
- ClassroomAgent：组织课件、例题、实操和复盘。
- SlideWriterAgent：生成课件页内容。
- VisualDesignerAgent：生成页面视觉结构和演示提示。
- VisualizationAgent / InteractiveWidgetRouter：选择并生成图解、模拟、代码、时间线或 3D 演示。
- ExerciseAgent：生成选择题、解析和提示。
- EvaluationAgent：评估答题、实操和复盘证据。
- MemoryAgent：写回学习记录、画像版本和个人知识库。
- SafetyAgent：检查来源、边界、幻觉和学术安全。

Agent 运行记录持久化在 `agent_tasks` 表中，便于教师端、调试和参赛展示说明。

## 14. 数据持久化模块

平台使用 PostgreSQL 作为主数据库，使用 JSONB 存储 AI 生成结构化内容，使用 pgvector 存储文档向量。

核心持久化对象：

- 用户：`users`
- 学生画像：`student_profiles`、`student_profile_versions`
- 课程知识库：`courses`、`course_chapters`、`knowledge_points`、`knowledge_documents`、`document_chunks`
- 知识库导入任务：`knowledge_import_jobs`
- 完整工作流：`workflow_sessions`
- 生成资源：`generated_resources`
- Agent 任务：`agent_tasks`
- 学习路径：`learning_paths`
- 答题记录：`answer_records`
- 研究方向：`research_directions`、`research_direction_templates`
- 项目计划：`project_plan_sessions`
- 学习项目：`learning_projects`
- 学习清单：`learning_syllabus_versions`、`learning_syllabus_items`、`learning_syllabus_operations`
- 课堂：`classroom_sessions`、`classroom_resources`、`classroom_submissions`
- 每日计划：`daily_learning_plans`、`daily_learning_plan_items`
- 文献：`literature_papers`
- 科研工具运行：`research_tool_runs`

## 15. 安全、错误处理与防幻觉设计

系统当前遵循 fail-closed 原则：

- AI API Key 未配置时返回明确错误。
- 附件解析失败时返回明确错误，不用文件名猜内容。
- 知识库检索失败或字段缺失时返回结构化错误。
- 模型 JSON 不符合 schema 时返回 LLMResponseError。
- 课堂演示缺少节点、边、帧或 3D 场景时直接失败，不生成默认替代内容。
- 前端 API 调用失败会弹出错误信息，方便按错误码定位问题。
- 推荐资源和引用链接要求真实链接，不允许编造 DOI、官网或搜索链接。

## 16. 部署模块

项目提供 Docker Compose 生产部署：

- PostgreSQL + pgvector。
- FastAPI backend。
- Vue frontend。
- Caddy 反向代理。

后端 Dockerfile 默认跳过 `fonts-noto-cjk`，避免小带宽服务器在 50MB+ 字体包下载阶段超时。如确需完整 Noto CJK 字体，可在 `.env.production` 中设置：

```env
INSTALL_CJK_FONTS=true
```

常用部署命令：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production build
docker compose -f docker-compose.prod.yml --env-file .env.production up -d
```

## 17. 典型用户使用链路

### 17.1 新领域学习

1. 登录系统。
2. 进入探索方向。
3. 输入学习目标并上传参考资料。
4. AI 流式生成项目计划。
5. 用户通过对话调整计划。
6. 构建学习项目。
7. 进入项目主页。
8. 查看学习清单。
9. 点击学习项进入课堂。
10. 学习动态课件。
11. 生成互动演示。
12. 完成选择题、实操和复盘。
13. 系统更新学习状态、错题和画像。

### 17.2 科研项目入门

1. 输入科研方向。
2. 系统生成项目计划。
3. 结合文献、课程知识库和上传资料生成学习清单。
4. 每个学习项生成课堂、例题、演示和实操。
5. 科研工具辅助生成技术路线、实验方案、评价指标和阶段计划。
6. 后续通过模拟答辩/面试类课堂训练开题、中期和答辩问题。

### 17.3 每日学习

1. 进入每日计划。
2. 查看今日继续任务。
3. 根据计划进入课堂。
4. 完成课堂学习。
5. 系统自动计算项目进度。
6. 逾期或提前任务可在计划页调整日期。
