# 智研星链：面向 AI4S 课程学习的个性化资源生成与学习多智能体平台初步计划书

## 1. 项目定位

本项目拟建设一个面向高校学生、任课教师和课程管理者的个性化学习资源生成与学习多智能体平台。平台不再定位为传统科研管理系统，而是围绕 A3 赛题“基于大模型的个性化资源生成与学习多智能体系统开发”，聚焦高校专业课程学习过程中的资源过载、学习路径不清晰、不同学生基础差异大、缺少即时辅导和学习效果反馈等问题。

平台的大方向仍然保留“AI4S 科研训练”特色，但落点从“科研项目全流程管理”调整为“AI4S 课程学习与科研入门训练”。初赛阶段建议以一门完整课程作为主场景，例如 **《人工智能与 AI4S 实践》**，围绕机器学习基础、深度学习、无线感知、智慧健康、实验复现和课程项目等内容，构建课程知识库、学生画像、个性化学习路径、多模态资源生成、智能辅导和学习效果评估闭环。

我认为现阶段应该先快速搭建“可完整演示的学习智能体系统”，让评委看到 A3 赛题要求中的核心能力：对话式学习画像、多智能体协同、至少 5 种类型的个性化资源生成、动态学习路径、精准资源推送、即时辅导、学习效果评估、防幻觉机制和完整文档支撑。同时保留 AI4S 课程特色，使项目和普通题库系统、普通 AI 聊天学习助手形成差异。

## 2. 简略的需求和竞品分析

高等教育中的学习资源越来越多，但学生并不一定能高效使用这些资源。课程 PPT、教材章节、实验指导书、论文、网课、题库、代码仓库和 AI 工具分散在不同平台中，学生常常面临三个问题：

- 不知道自己当前真正薄弱的知识点是什么。
- 不知道按什么顺序学习、复习和实践。
- 找到资源后仍然缺少适合自己基础和目标的讲解、练习和反馈。

传统教学平台通常更擅长发布课件、提交作业和统计成绩，但难以根据学生画像生成差异化资源。普通大模型聊天工具虽然能回答问题，却容易变成“一问一答”的临时辅助，缺少课程知识库约束、学习路径规划、持续画像更新、资源沉淀和学习效果追踪。部分智能教育产品已经开始提供个性化推荐和答疑，但在“多智能体协作生成多模态资源”“课程项目实践材料生成”“学习行为驱动的路径动态调整”等方面仍有提升空间。

因此，本项目计划从高校 AI4S 入门课程切入，将课程学习、实验实践和科研入门结合起来。系统通过多智能体协同完成学生画像构建、课程知识诊断、个性化资源生成、路径规划、答疑辅导、练习评估、资源推荐和教师端教学洞察，形成一条“画像识别 -> 资源生成 -> 路径学习 -> 智能辅导 -> 效果评估 -> 路径更新”的闭环。

## 3. 核心故事线

主演示样例建议固定为《人工智能与 AI4S 实践》课程中的“基于 WiFi CSI 的跌倒检测与健康预警”学习单元。这个样例能延续原计划中 AI4S、无线感知和健康安全的特色，同时更符合 A3 赛题要求：学生不是直接做完整科研管理流程，而是在课程学习系统中获得个性化讲解、练习、实验案例和学习路径。

演示流程如下：

1. 学生首次进入系统，通过自然语言对话说明自己的专业、课程目标、已有基础、学习时间、偏好资源类型和当前困惑。
2. 画像 Agent 自动提取并生成动态学习画像，至少包含知识基础、学习目标、认知风格、易错点、实践能力、资源偏好、学习节奏、兴趣方向等维度。
3. 系统根据课程知识库和学生画像，诊断学生在“机器学习基础、信号处理、深度学习、实验评价指标、Python 实践”等方面的掌握情况。
4. 路径规划 Agent 生成个性化学习路径，例如先补“分类任务与评价指标”，再学习“CSI 数据特征”，再进入“跌倒检测模型实践”。
5. 资源生成 Agent 群协同生成至少 5 种类型的个性化学习资源：课程讲解文档、知识点思维导图、分层练习题、拓展阅读材料、代码实操案例、多模态讲解视频脚本或动画分镜。
6. 学生选择“我不理解召回率为什么比准确率更重要”，智能辅导 Agent 基于课程知识库给出文字解释、图解说明和针对性小例题。
7. 学生完成系统生成的小测和代码实验，评估 Agent 根据答题、实验结果和反馈更新学习画像。
8. 系统发现学生在“混淆矩阵”和“数据集划分”上仍有薄弱点，自动调整下一轮资源推送，减少重复讲解，增加专项练习和实验检查清单。
9. 教师端查看班级学习驾驶舱，了解不同学生的知识短板分布、资源使用情况、学习路径进度和高风险学生。
10. 课程资源管理员或教师可以上传课程 PPT、实验指导书、论文摘要、样例代码和题库，系统通过 RAG 和内容安全机制保证回答有来源、可追溯、不过度编造。

这条故事线可以在 7 分钟演示视频中完整展示 A3 的核心要求：画像、资源生成、多智能体、路径推荐、辅导、评估和教师洞察。

## 4. 平台模块设计

### 4.1 学习工作台

学习工作台是学生进入系统后的首页，展示当前课程、学习路径、待完成任务、推荐资源、薄弱知识点、最近练习结果和 AI 建议。它不是普通课程门户，而是围绕学生画像动态变化。

学生端重点展示“下一步学什么、为什么学、用什么资源学、完成后如何验证”。教师端重点展示班级知识掌握分布、资源生成情况、学生学习风险和课程资源质量。管理端主要展示课程建设进度、知识库覆盖情况、智能体运行情况和内容安全统计。

### 4.2 对话式学习画像中心

该模块用于满足 A3 赛题中“对话式学习画像自主构建”的要求。系统不让学生填写复杂表单，而是通过自然语言对话抽取画像信息。

画像维度初赛建议至少包含：

- 知识基础：数学、编程、机器学习、课程前置知识掌握情况。
- 学习目标：应试、课程项目、科研入门、竞赛准备、毕业设计铺垫等。
- 认知风格：偏文字讲解、图示理解、案例驱动、代码实践或视频讲解。
- 易错点偏好：概念混淆、公式推导、代码实现、实验设计、结果解释等。
- 实践能力：Python、深度学习框架、数据处理、实验复现能力。
- 学习节奏：每周可投入时间、希望的学习强度、阶段截止日期。
- 资源偏好：讲义、思维导图、题库、视频脚本、代码案例、论文导读等。
- 兴趣方向：无线感知、智慧健康、计算机视觉、自然语言处理、科学计算等 AI4S 方向。

画像需要支持“随学随新”。学生完成练习、提出问题、阅读资源、提交实验结果后，系统应更新掌握度、易错点和推荐策略。

### 4.3 课程知识库与资源素材库

初赛阶段自行构造一门完整高校课程的初始知识库，建议课程为《人工智能与 AI4S 实践》。知识库内容包括：

- 课程大纲、章节结构和知识点树。
- 教材节选或自编讲义。
- 课程 PPT 摘要。
- 实验指导书和样例代码说明。
- 典型题目和解析。
- AI4S 方向案例，例如 WiFi CSI 跌倒检测、医学图像分类、材料性质预测等。
- 拓展阅读材料和论文摘要。
- 学术规范、实验报告规范和课程项目评分标准。

系统需要提供来源展示和引用追踪。学生提问或 Agent 生成资源时，优先检索课程知识库，再结合大模型生成内容，避免无依据生成。

### 4.4 多智能体资源生成中心

该模块是 A3 初赛最核心的深挖模块。平台需要明确多智能体架构，而不是单一聊天机器人。建议设计以下 Agent：

- 画像 Agent：从对话和学习行为中抽取画像维度并持续更新。
- 诊断 Agent：根据课程知识点、练习结果和学生提问判断薄弱环节。
- 路径规划 Agent：生成阶段学习目标、学习顺序和资源组合。
- 讲解 Agent：生成适配学生基础的课程讲解文档。
- 题目 Agent：生成选择题、判断题、简答题、代码填空题和项目思考题。
- 多模态 Agent：生成思维导图、PPT 大纲、图解说明、视频脚本或动画分镜。
- 代码实践 Agent：生成课程实验案例、代码骨架、调试提示和实验检查清单。
- 评估 Agent：批改练习、总结学习效果并提出下一轮优化建议。
- 安全与事实校验 Agent：检查生成内容是否偏离课程知识库、是否存在幻觉或不适合发布。

初赛必须展示至少 5 种类型的个性化资源生成：

1. 专业课程讲解文档。
2. 知识点思维导图。
3. 分层练习题与解析。
4. 拓展阅读材料与论文导读。
5. 代码类实操案例。
6. 多模态教学视频脚本或动画分镜。
7. 课程项目学习材料，例如实验方案、数据处理流程和报告模板。

生成结果应以卡片化方式展示，并标注适用画像、关联知识点、生成依据和建议使用顺序。

### 4.5 个性化学习路径与资源推送

路径规划模块根据学生画像、课程知识树和学习效果评估结果，生成动态学习路径。路径不是简单章节目录，而是根据学生差异调整顺序和资源类型。

例如同样学习“跌倒检测评价指标”：

- 编程基础弱的学生：先看混淆矩阵图解，再做手算练习，最后进入 Python 指标计算。
- 实践能力强但理论薄弱的学生：先跑代码实验，再反推准确率、召回率、F1 值的含义。
- 目标是课程项目的学生：重点推送数据采集方案、实验变量控制和报告模板。
- 目标是科研入门的学生：增加论文导读、对比实验和局限性分析。

资源推送需要说明推荐理由，例如“因为你在最近两次练习中混淆了召回率和准确率，系统建议先完成专项图解和 5 道针对性练习”。

### 4.6 智能辅导中心

智能辅导中心用于即时回答学生学习过程中的问题。初赛可以先以文本和图解为主，复赛再接入语音、短视频或更复杂的多模态生成。

辅导输出建议包含：

- 简明回答。
- 分步骤解释。
- 图解或类比说明。
- 关联知识点。
- 来源材料。
- 针对学生画像的小练习。
- 下一步推荐资源。

系统需要避免直接给出作业最终答案。对于作业、实验报告和课程项目，辅导 Agent 更适合提供思路、检查清单、错误定位和学习建议，而不是替学生完成提交内容。

### 4.7 学习效果评估与动态优化

该模块用于满足 A3 可选加分项“学习效果评估”。系统跟踪学生的练习测试、资源使用、提问内容、实验提交和反馈评价，从多个维度评估学习效果：

- 知识掌握度：各知识点的掌握水平。
- 练习正确率：题目完成情况和错因分类。
- 实践完成度：代码实验、项目任务和报告材料完成情况。
- 学习投入度：学习时长、资源使用频次、路径完成度。
- 问题质量：提问是否从概念性问题逐步进入应用和分析问题。
- 迁移能力：是否能把知识用于新的案例或课程项目。

评估结果不只展示分数，还要反向驱动画像更新、路径调整和资源再生成，形成持续优化机制。

### 4.8 教师与课程管理中心

教师端支持课程资源上传、知识点维护、班级学习情况查看、资源生成审核、学生风险预警和教学改进建议。

教师可以看到：

- 班级整体知识点掌握热力图。
- 高频易错点和高频提问。
- 不同学生画像分布。
- 资源使用效果统计。
- 学习路径完成情况。
- 需要教师介入的学生和原因。

课程管理中心不是传统教务系统，而是辅助教师了解学生真实学习差异，减少重复答疑和资源整理成本。

### 4.9 防幻觉、内容安全与开源合规

A3 明确要求系统具备防幻觉和内容安全过滤机制。初赛阶段建议实现以下策略：

- RAG 优先：课程相关问题优先基于知识库检索结果回答。
- 来源展示：资源生成结果标注依据材料、知识点和引用片段。
- 事实校验：安全与事实校验 Agent 检查生成内容是否与课程资料冲突。
- 置信度提示：低置信度内容提示“需要教师确认”。
- 敏感内容过滤：过滤违规、不适合教学和不符合学术规范的内容。
- 作业边界提醒：避免替学生直接完成应提交作业或实验报告。
- 开源合规说明：如使用开源框架、模型、可视化组件或 AI Coding 工具，在提交文档中列出名称、来源和协议。

### 4.10 AI4S 课程项目实践中心

为保留原项目的 AI4S 特色，平台设置课程项目实践中心。它不是完整科研管理系统，而是服务课程学习的实践单元。

学生在完成某个学习路径后，可以进入实践中心，生成与课程项目相关的材料：

- 项目背景讲解。
- 技术路线学习材料。
- 实验数据说明。
- 代码实操案例。
- 评价指标练习。
- 实验报告结构检查。
- 答辩问题模拟。

例如“WiFi CSI 跌倒检测”实践项目可以生成 CSI 基础讲解、人体活动识别思维导图、数据预处理代码骨架、准确率/召回率练习题、拓展阅读论文导读和实验报告检查清单。

## 5. 初赛初步目标

初赛必须完成：

- 角色体系：学生、任课教师、课程资源管理员、平台管理者。
- 数据模型：用户、课程、章节、知识点、学习画像、学习路径、资源卡片、资源生成任务、练习题、答题记录、实验案例、学习行为、辅导会话、评估报告、知识库文档、内容安全记录。
- 核心页面：学习工作台、画像对话页、课程知识库、资源生成中心、学习路径页、智能辅导页、练习评估页、教师驾驶舱、课程项目实践页。
- 核心 AI 能力：画像抽取、知识点诊断、多智能体任务编排、课程讲解生成、思维导图生成、练习题生成、拓展阅读生成、代码案例生成、视频脚本或动画分镜生成、RAG 问答、学习路径规划、学习效果评估、防幻觉校验。
- 业务闭环：学生对话建档 -> 系统生成学习画像 -> 诊断知识短板 -> 规划学习路径 -> 多智能体生成资源 -> 学生学习和提问 -> 完成练习/实验 -> 评估学习效果 -> 更新画像和路径 -> 教师查看班级洞察。
- 测试数据：至少一门完整课程的知识库与模拟学生数据，建议覆盖《人工智能与 AI4S 实践》课程的 6-8 个章节。

初赛可以只做入口或半成品的部分：

- 真实短视频自动生成。
- 语音输入和实时语音辅导。
- 大规模真实学生行为采集。
- 完整移动端适配。
- 与学校真实教务系统对接。
- 复杂学习分析模型训练。
- 高精度自动批改主观题。

初赛提交文档中还需要单独说明开发过程中使用的 AI Coding 工具、讯飞相关工具、开源框架、模型来源和协议要求，避免在作品评审时被认为缺少合规说明。

## 7. 复赛深化方向

如果通过初赛，后续可以沿以下方向深化：

- 深化多模态生成：接入更完整的图像、动画、短视频或语音讲解生成能力。
- 深化学习画像：引入更多学习行为特征，支持更细粒度的画像更新和长期学习档案。
- 深化学习效果评估：加入主观题半自动批改、代码运行结果分析和实验报告结构评估。
- 深化课程知识库：扩展更多 AI4S 课程模块，如医学影像、材料智能、科学计算和环境智能。
- 深化多智能体编排：可视化展示画像 Agent、诊断 Agent、路径 Agent、资源 Agent、辅导 Agent、评估 Agent、校验 Agent 的协作过程。
- 深化防幻觉机制：增加引用一致性检查、教师审核流和低置信度回答拦截。
- 深化教师端：提供课程资源建设建议、课堂教学改进建议和个性化作业推荐。
- 深化实践项目：支持学生从课程学习自然过渡到大创、毕业设计或科研训练，但仍以学习支持为主。

## 8. 重点问题说明

### 8.1 用户角色及其需求

**学生用户**

学生的核心需求是知道自己该学什么、怎么学、用什么资源学、学完如何确认自己真的掌握。学生需要对话式画像、个性化学习路径、适配自己基础的讲解、分层练习、代码案例、拓展阅读、即时答疑和学习效果反馈。

**任课教师**

教师的核心需求是降低课程资源整理和重复答疑成本，同时了解学生真实学习差异。教师需要课程知识库管理、资源生成审核、班级知识掌握统计、高频错因分析、学生风险预警和教学改进建议。

**课程资源管理员**

课程资源管理员负责维护课程资料、题库、实验文档、样例代码、拓展阅读和知识库质量。他们需要文档上传、标签维护、资源版本管理、引用来源管理和内容安全检查。

**平台管理者**

平台管理者关注系统运行质量、智能体调用情况、内容安全、课程覆盖、资源生成效率和用户反馈。管理端不进入具体教学细节，而是提供运行监控和平台级统计。

### 8.2 多智能体系统如何体现

本项目不能只做一个大模型聊天框。多智能体的价值在于把学习支持拆成多个可解释、可协作、可评估的角色。

建议在演示中明确展示一次完整协作过程：

1. 画像 Agent 读取学生对话，生成画像。
2. 诊断 Agent 结合课程知识树判断薄弱点。
3. 路径规划 Agent 生成学习顺序。
4. 资源生成 Agent 群分别生成讲义、题目、思维导图、代码案例和拓展阅读。
5. 校验 Agent 检查内容是否有来源、是否偏离课程资料。
6. 评估 Agent 根据学生练习结果更新画像。
7. 路径规划 Agent 再次调整下一步资源。

页面上可以用“智能体协作轨迹”展示每个 Agent 的输入、输出、状态和耗时，使评委直观看到系统不是单点问答，而是具备流程编排能力。

### 8.3 个性化资源生成如何避免泛泛而谈

资源生成必须与学生画像、课程知识点和学习目标绑定。每张资源卡建议展示：

- 资源类型。
- 适用学生画像。
- 关联知识点。
- 生成依据。
- 学习目标。
- 推荐使用顺序。
- 预计学习时长。
- 配套练习或评估方式。

例如系统生成“召回率与准确率讲解文档”时，不应只输出通用百科解释，而应根据学生画像调整表达方式：

- 对数学基础弱的学生，减少公式推导，增加混淆矩阵图解。
- 对代码实践强的学生，增加 Python 指标计算案例。
- 对课程项目学生，强调跌倒检测中漏检风险为什么更重要。

### 8.4 学习路径和资源推送如何动态调整

学习路径的初始版本由画像和课程目标生成，后续由学习行为和评估结果驱动更新。系统至少需要体现三类调整：

- 知识短板调整：某知识点错题多，则插入补救资源和专项练习。
- 资源偏好调整：学生更常完成图解和代码资源，则提高相似资源优先级。
- 目标变化调整：学生从“通过考试”转向“完成课程项目”，则增加实验案例和项目材料。

路径调整需要可解释，不能只给一个新列表。系统应说明“为什么改变推荐”。

### 8.5 防幻觉与内容安全实现方案

防幻觉机制建议作为初赛重点说明，因为 A3 明确提出该要求。实现上可以采用“知识库检索 + 生成 + 校验 + 来源展示”的流程。

具体策略：

- 课程内问题必须先检索知识库。
- 生成内容必须绑定知识点和来源材料。
- 对无来源结论提示低置信度。
- 对公式、代码和实验指标进行规则检查或二次校验。
- 对可能误导学生的内容进入教师审核。
- 对作业代写、实验结果编造、虚假参考文献等内容进行拦截或提醒。

这样既能满足学习辅助，也能体现高校教学场景下的责任边界。

### 8.6 开发工具与合规说明

A3 赛题对开发环境不做限制，但要求开发过程中使用的其他 AI 辅助工具需选用科大讯飞相关工具，并且如使用开源项目、前沿 AI 工具或框架，需要在提交文档显著位置标注名称、来源和协议。

因此初赛文档建议单独设置“工具与合规说明”小节，列出：

- 智能体开发框架和多智能体编排方式。
- 大模型、嵌入模型、多模态生成工具或讯飞相关工具。
- AI Coding 工具使用情况和使用边界。
- 前端框架、后端框架、数据库、向量库和可视化组件。
- 开源协议、模型协议和第三方资源来源。
- 课程知识库中自构造内容、公开资料和引用资料的边界。

### 8.7 课程样例与数据构造建议

初赛需要自行构造至少一门完整高校专业课程的初始知识库。建议课程为《人工智能与 AI4S 实践》，章节可以设计为：

1. 人工智能与 AI4S 概论。
2. Python 数据处理基础。
3. 机器学习分类任务。
4. 深度学习基础。
5. 信号处理与无线感知入门。
6. WiFi CSI 跌倒检测案例。
7. 实验评价指标与结果分析。
8. 课程项目报告与展示规范。

每章至少准备知识点说明、讲义摘要、练习题、实验或案例材料、拓展阅读。这样既满足 A3 对课程数据的要求，也能延续原项目的 AI4S 特色。

### 8.8 初赛演示重点

7 分钟演示视频建议按以下节奏：

1. 30 秒说明学生个性化学习痛点和平台定位。
2. 60 秒展示对话式画像生成。
3. 60 秒展示课程知识诊断和学习路径规划。
4. 120 秒展示多智能体生成 5 种类型资源。
5. 60 秒展示智能辅导和来源引用。
6. 60 秒展示练习评估、画像更新和路径调整。
7. 60 秒展示教师驾驶舱、防幻觉机制和多智能体协作轨迹。

演示中要反复强调本项目与 A3 赛题要求的对应关系：个性化、多模态、多智能体、学习路径、资源推送、辅导评估、防幻觉和可运行系统。
